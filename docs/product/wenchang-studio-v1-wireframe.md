# 文昌 Studio v1 低保真原型

## 原型目标

这版原型只验证一件事：普通创作者不理解文昌 skills、prompt、`content_state`，也能通过界面完成一次内容创作任务。

v1 不做自动发布。所有页面都围绕“把内容做到可手动发布前一刻”设计。

## 信息架构

```text
首页 / 项目列表
  -> 新建项目
  -> 项目工作台
       -> 素材箱
       -> 阶段进度
       -> 决策卡片
       -> 产物箱
       -> 专家模式
  -> 模板管理
       -> 官方模板
       -> 我的模板
       -> 模板编辑
  -> Runner 连接状态
```

## 页面 1：首页 / 项目列表

### 目标

让用户快速开始一个内容项目，并能找回之前的项目。

### 页面结构

```text
文昌 Studio

[新建内容项目]

最近项目
--------------------------------------------------
标题                         阶段       更新时间
AI 记忆会改变工作方式吗       诊文       今天 16:20
Codex 接管我的工作台          出刊       昨天 22:10
不要把学习外包给 AI           已完成     05-26
--------------------------------------------------

模板
[Human3.0 公众号判断文] [AI 工具体验复盘] [小红书知识卡片]

本地 Runner
状态：已连接 / 未连接
[查看连接方式]
```

### 关键交互

- 点击“新建内容项目”进入项目创建页。
- 点击项目进入项目工作台。
- Runner 未连接时，允许创建项目，但执行按钮置灰，并提示先连接本地 Runner。

## 页面 2：新建项目

### 目标

把复杂 prompt 输入变成五个入口 + 少量必要信息。

### 页面结构

```text
新建内容项目

你现在有什么？

[不知道写什么]
[有一个主题]
[有热点文章 / 链接]
[有一篇初稿]
[只做发布前检查 / 分发包]

目标平台
(*) 公众号   ( ) 小红书   ( ) 知乎   ( ) 多平台分发

选择模板
(*) Human3.0 公众号判断文
( ) AI 工具体验复盘
( ) 小红书知识卡片
( ) 知乎观点回答
( ) 我的模板...

输入材料
标题 / 主题：
[                                              ]

链接：
[                                              ]

初稿 / 补充材料：
[                                              ]

[创建项目并开始分析]
```

### 小白默认值

- 默认平台：公众号。
- 默认模板：Human3.0 公众号判断文。
- 默认执行方式：本地 Codex Runner。
- 默认先进入总控判断，不直接生成全文。

### 表单校验

- “不知道写什么”：至少需要主题方向或账号领域。
- “有一个主题”：必须有主题。
- “有热点文章 / 链接”：必须有链接或粘贴材料。
- “有一篇初稿”：必须有初稿正文。
- “发布前检查”：必须有正文或已有产物。

## 页面 3：项目工作台

### 目标

让用户看到当前进度、需要判断的事项和已经生成的内容资产。

### 页面结构

```text
项目：AI 记忆会改变普通人的工作方式吗
模板：Human3.0 公众号判断文
平台：公众号
状态：等待你确认

------------------------------------------------------------
左：素材箱              中：当前阶段              右：需要你决定
------------------------------------------------------------
主题                   阶段进度                  决策卡片
链接                   探脉  定题  采证          [选题方向确认]
初稿                   立骨  起稿  诊文          下面三个角度选一个：
补充材料               整章  出刊  分发          ( ) 写产品功能变化
                                               (*) 写工作流变化
[添加材料]             当前阶段：定题            ( ) 写隐私风险

                       已完成：
                       - 识别入口为热点链接
                       - 生成 3 个可写角度

                       下一步：
                       - 你确认角度后进入采证

                                               [确认选择]
                                               [先不继续]
------------------------------------------------------------
底部：产物箱
[选题 brief] [采证报告] [初稿] [诊文报告] [发布包]
```

### 工作台原则

- 中间区域只展示高层进度和本轮结论。
- 右侧只展示用户必须判断的事情。
- 产物箱保存阶段产物，避免内容散落在聊天中。
- 专家模式默认折叠。

## 页面 4：决策卡片

### 目标

把文昌的停顿节点变成用户能理解的选择。

### 卡片类型

#### 选题确认

```text
需要你确认：选题方向

系统判断这个素材有 3 个可写角度。建议选第 2 个，因为它更贴近你的账号长期方向。

( ) AI 产品功能更新
(*) AI 如何改变普通人的工作流
( ) AI 记忆带来的隐私风险

确认后影响：
后续采证、起稿和标题都会围绕这个角度展开。

[确认并继续采证] [返回修改材料]
```

#### 采证不足

```text
需要你确认：采证可信度偏低

目前缺少反向证据，不能直接写成强判断文章。

(*) 继续补采证
( ) 降级为个人观点文
( ) 暂停这个选题

[确认]
```

#### 诊文建议

```text
需要你确认：是否接受大幅修改

诊文结论：当前初稿方向可用，但开头和结构需要重排。

(*) 接受整章编辑
( ) 只做轻微润色
( ) 暂停，先看诊文报告

[确认]
```

#### 分发资产

```text
需要你确认：是否生成二次分发资产

公众号发布包已完成。是否继续生成小红书卡片结构和知乎改写建议？

[生成小红书卡片结构] [生成知乎改写建议] [暂不生成]
```

### 决策记录

每次点击确认后，后台写入：

```yaml
decisions:
  - stage: 定题
    question: 选择哪个选题方向
    user_choice: AI 如何改变普通人的工作流
    impact: 后续采证、起稿和发布包围绕该角度推进
```

## 页面 5：产物箱

### 目标

把可交付内容集中管理，方便复制、导出和二次修改。

### 页面结构

```text
产物箱

[公众号正文] [发布包] [小红书卡片结构] [知乎改写建议] [诊文报告] [状态快照]

公众号正文
--------------------------------------------------
标题：
AI 不是开始写代码，而是开始接管你的工作台

正文：
...
--------------------------------------------------

[复制正文] [下载 Markdown] [导出 HTML] [生成发布检查]
```

### 发布包内容

```text
标题候选
摘要
封面文案
标签
朋友圈文案
评论区引导
发布前检查清单
```

### 边界

- 不展示“发布到公众号”按钮。
- 不接平台账号授权。
- 所有输出以手动复制或文件导出结束。

```text

### 页面结构

[运行测试任务]

```

## 端到端流程

### 流程 A：热点链接到公众号发布包

```text
新建项目
-> 选择“有热点文章 / 链接”
-> 选择 Human3.0 公众号判断文模板
-> 粘贴链接
-> Runner 调用文昌总控
-> 系统给出选题方向决策卡
-> 用户确认
-> 进入采证、起稿、诊文、出刊
-> 产物箱生成公众号正文和发布包
-> 用户手动导出
```

### 流程 B：已有初稿诊断

```text
新建项目
-> 选择“有一篇初稿”
-> 粘贴正文
-> Runner 调用诊文链路
-> 系统给出诊断报告
-> 用户确认是否整章编辑
-> 产物箱生成编辑后正文和发布包
```

### 流程 C：从主题找选题

```text
新建项目
-> 选择“有一个主题”
-> 输入主题和目标读者
-> Runner 调用定题链路
-> 系统给出 3 个可写方向
-> 用户确认
-> 后续流程继续推进到发布包
```

## 空状态与失败状态

### Runner 未连接

提示：

```text
本地 Runner 尚未连接。你可以先创建项目和整理素材，但暂时不能执行文昌流程。
```

### 执行失败

提示：

```text
本轮执行失败。

原因：本地 Codex Runner 没有返回有效的 content_state。
影响：项目状态未推进，上一阶段产物仍然保留。
下一步：重试本阶段，或打开专家模式查看日志。
```

### 需要用户补材料

提示：

```text
当前材料不足以继续。

缺少：目标读者、主题方向或初稿正文。
补充后可以继续执行。
```

## MVP 验收

- 用户能在 3 分钟内创建第一个项目。
- 用户不需要输入 skill 名称。
- 用户能看懂当前阶段和下一步。
- 至少 3 类决策卡片可用：选题确认、采证不足、诊文建议。
- 至少 3 类产物可见：公众号正文、发布包、诊文报告。
- 没有任何自动发布入口。
