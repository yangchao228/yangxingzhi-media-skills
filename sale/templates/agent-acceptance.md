# Agent 任务委托与验收模板

适合希望减少找结果、查证据和重复沟通的任务。先在低影响、可撤回的任务中试用；已有信息直接复用，简单任务只保留影响判断的字段，不要求用户重新填一遍。

## 开工前：委托单

复制下面的提示，结合当前任务填写：

```text
请先从当前对话和指定材料整理委托单，再按已有授权推进。

任务目标：<本次要得到什么>
资料或文件范围：<本次需要读取、允许修改的范围>
完成条件：<能用事实、文件或实际结果核对的条件>
交付位置与格式：<文件、目录、链接或报告>
已授权动作：<按当前任务记录，不扩大授权>
关键限制与暂停条件：<缺关键证据、影响范围改变或超出授权等真实条件>

已有明确默认和授权时继续处理，不重复确认。
缺少影响完成判断的信息时，先说明缺口，不自行降低标准。
上传、保存平台草稿、发布、Git提交和推送分别按已授权范围处理。
模板默认项、示例及整理出的计划不构成新增授权；沿用当前任务对只读、仅草稿、不提交或不推送的明确限制。
```

## 交付时：给出可核对的结果

```text
结果：文件、链接或修改位置。
完成范围：本次实际完成的内容。
证据：原始来源、实际执行的检查命令及结果，或可复现步骤。
限制：未执行的检查、失败项、不确定性及未覆盖路径。
需决定事项：只列会影响下一步的选择，没有则写“无”。
详细记录：需要追查时可打开的位置。
```

自检和独立核验分别记录；本地验证、平台回读和公开发布分别说明。没有执行的检查标为未执行，缺证据不能写“全部通过”。重要异常应直接报告，不藏在简短结论后面。

## 验收时：按任务决定检查深度

| 任务情况 | 可采用的检查方式 | 加深检查的条件 |
| --- | --- | --- |
| 本地、低影响、容易撤回，规则已验证 | 规则检查后抽查 | 首次执行、新规则、出现错误或证据不全 |
| 涉及新事实、核心行为或对外引用 | 回到原始来源及实际结果 | 来源矛盾、无法复现或影响范围扩大 |
| 公开发布、重要删除或对外承诺 | 核对具体对象、结果与已有授权 | 超出原有授权或存在未明确的不可恢复影响 |

此表用于安排检查投入；具体任务仍遵循其实际要求和授权。

## 复盘：下次只改一个环节

- 找结果花时间：改结果索引和交付位置。
- 查证据花时间：让主张与依据逐条对应。
- 方向反复变：提前确认会影响后续工作的选择。
- 小问题打断多：合并到约定检查点，紧急异常及时报告。
- 填卡比原任务还费事：删除不影响判断的字段。
