# 01 短视频脚本细稿：Agent 会不会自己变强

状态：可拍摄 / 可配屏录
默认制作：屏录 + 字幕 + 旁白，低成本先跑

## 小红书视频

标题：别被自进化吓到，先看它到底需要什么条件

时长：60-75 秒

```text
0-3 秒：
最近很多人在讲 Agent 自我进化，但我会先问一个更朴素的问题：它靠什么知道自己变好了？

3-13 秒：
如果一个任务没有验收标准，没有反馈记录，没有人审边界，Agent 多跑几轮也只是多试几次。

13-35 秒：
真正接近自改进的系统，通常有两层。
内环负责做事：读资料、写稿、跑测试、输出结果。
外环负责复盘：读取失败记录，找重复问题，再决定要不要更新 Skill、模板或规则。

35-55 秒：
普通人今天能做的第一步，不是换更贵的模型，是给自己的 Agent 建一个错题本。
每次失败记录六项：任务目标、预期结果、实际结果、验证证据、失败类型、下一次规则。

55-70 秒：
失败留下来，才会变成经验。
评论区留“错题本”，我后面把模板整理成可复制版。
```

镜头建议：

- 开头：屏幕大字“Agent 会自己变强吗？”
- 中段：展示“内环 / 外环”双循环草图。
- 方法段：展示反馈日志 6 个字段。
- 结尾：展示“评论：错题本”。

字幕关键词：

- 可验证
- 反馈记录
- 外环复盘
- 人工审核
- Agent 错题本

## 抖音视频

标题：Agent 会自我进化？先看有没有反馈系统

时长：35-50 秒

```text
0-3 秒：
很多人说 Agent 会自我进化，我建议先别急着兴奋。

3-10 秒：
没有反馈系统的 Agent，不是在成长，只是在反复尝试。

10-25 秒：
比如让 Agent 修代码。
如果它没有测试结果、错误日志和修改记录，它根本不知道哪次改动有效。
让 Agent 写内容也一样。
如果没有来源检查、风格规则和禁用句式，它下次还会犯同样的错。

25-40 秒：
先做三件事：
定义验收标准。
记录失败原因。
把重复错误写进 Skill 或模板。

40-48 秒：
Agent 想长记性，第一步不是自由更多，是反馈更清楚。
```

镜头建议：

- 前 3 秒大字：“自我进化？先看反馈”
- 中段：代码测试结果 / 文章检查清单快速切换。
- 结尾：三项 checklist。

评论引导：

你希望 Agent 最先记住哪条规则？
