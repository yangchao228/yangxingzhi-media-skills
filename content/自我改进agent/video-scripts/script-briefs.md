# 第一季视频脚本 brief

## 01 Agent 会不会自己变强

### 小红书视频

标题：别被自进化吓到，先看它到底需要什么条件

脚本：

```text
开头：
最近很多人在讲 Agent 自我进化，但我会先问一个更朴素的问题：它到底靠什么知道自己变好了？

判断：
如果一个任务没有验收标准，没有反馈记录，没有人审边界，Agent 多跑几轮也只是多试几次。

案例：
真正接近自改进的系统，通常有两层：内环负责执行任务，外环负责读失败记录、找重复问题，再提出规则更新。

方法：
普通人今天能做的第一步，不是换工具，是给自己的 Agent 建一个错题本。每次失败记录目标、预期、实际、证据和下次规则。

收束：
想要模板，可以在评论区留“错题本”。下一条讲内环和外环到底怎么分。
```

镜头建议：屏录一个简化反馈日志表，再切到双循环草图。

### 抖音视频

标题：Agent 会自我进化？先看有没有反馈系统

脚本：

```text
开头：
很多人说 Agent 会自我进化，我觉得先别急着兴奋。

判断：
没有反馈系统的 Agent，不是在成长，只是在反复尝试。

例子：
比如让 Agent 修代码，如果它没有测试结果、错误日志和修改记录，它根本不知道哪次改动真的有效。

行动：
先做三件事：定义验收标准，记录失败原因，把重复错误写进 Skill 或模板。

收束：
Agent 想长记性，第一步不是自由更多，是反馈更清楚。
```

镜头建议：前三秒直接上大字“自我进化？先看反馈”。

## 02 从 Loop 到进化

### 小红书视频

标题：为什么会跑 Loop 的 Agent 还不算会成长

脚本：

```text
开头：
一个 Agent 会循环执行任务，不代表它真的在成长。

判断：
Loop 解决的是持续执行，自改进多了一层：把执行经验写回系统。

案例：
内环像日常工作：读文件、改代码、跑测试、继续下一轮。外环像周复盘：看过去哪些错误重复出现，再决定要不要更新 Skill。

方法：
判断一个 Agent 有没有成长，别只看它跑了多少轮，要看它有没有留下可复用的规则、模板或检查表。

收束：
下一次你设计 Agent 时，可以先画两层：执行层和复盘层。
```

镜头建议：用左右分屏展示“内环执行”和“外环复盘”。

### 抖音视频

标题：Agent 一直跑，不代表它在进步

脚本：

```text
开头：
Agent 一直跑，可能只是一直忙。

判断：
真正的进步，要看它有没有改变下一次的工作方式。

例子：
今天同样的错误修三次，明天还犯，这就不是成长。今天失败后写进 Skill，明天自动避开，才有意义。

行动：
给 Agent 加一个外环：定期读日志，找重复失败，生成规则更新建议，人审后再合并。

收束：
忙不等于进步，能沉淀才算进步。
```

镜头建议：用“忙碌循环”和“沉淀飞轮”两张卡切换。

## 03 Agent 错题本

### 小红书视频

标题：我会先给 Agent 加一个失败记录表

脚本：

```text
开头：
如果一个 Agent 同样的错误犯三次，我不会先怪模型。

判断：
我会先看自己有没有把失败整理成它下次能用的格式。

模板：
一个最小错题本记录六项：任务目标、预期结果、实际结果、验证证据、失败类型、下一次规则。

方法：
下次类似任务开始前，只加载相关失败记录，不把整段聊天历史塞进去。

收束：
评论区留“错题本”，我整理了一个 markdown 模板。
```

镜头建议：屏录 `feedback-log.md` 的字段，逐项高亮。

### 抖音视频

标题：你以为 Agent 不长记性，其实是没给它错题本

脚本：

```text
开头：
Agent 不长记性，很多时候不是模型问题。

判断：
是失败没有被结构化记录。

例子：
你只说“下次注意”，它很难执行。你写“遇到中文路径时先 ls -lb 核文件名”，它下次才有规则可用。

行动：
失败后别只骂一句，补三行：错在哪里，证据是什么，下次规则是什么。

收束：
能被复用的失败，才会变成经验。
```

镜头建议：用“下次注意”与“可执行规则”的对比字幕。

## 04 OpenClaw 个人 Agent

### 小红书视频

标题：让 Agent 每天复盘自己，最小系统怎么搭

脚本：

```text
开头：
个人 Agent 想长记性，不一定一上来就做复杂系统。

判断：
我会先搭一个低风险外环：每天读反馈日志，生成 Skill 更新建议，然后人来审核。

结构：
最小只需要四类文件：反馈日志、Skill 文件、更新审核表、变更记录。

方法：
日常 Agent 负责执行任务；外环 Agent 负责复盘重复失败；人负责决定规则能不能合并。

收束：
这套系统先跑内容诊文、周报整理、项目巡检这类低风险任务。
```

镜头建议：展示目录结构和每日复盘流程。

### 抖音视频

标题：个人 Agent 想长记性，先别全自动

脚本：

```text
开头：
很多人想让 Agent 自动改进，我建议第一步先别全自动。

判断：
最稳的起点是人审外环。

例子：
Agent 每天复盘失败日志，提出 Skill 修改建议，但合不合并由人决定。

行动：
先准备四个文件：反馈日志、Skill、审核表、更新记录。跑一周低风险任务再看效果。

收束：
自改进要先可控，再追求自动。
```

镜头建议：前三秒大字“别先全自动”。

## 05 边界与漂移

### 小红书视频

标题：最危险的 Agent，是没有停止条件的 Agent

脚本：

```text
开头：
自改进 Agent 最大的风险，不是它不改，是它乱改。

判断：
没有验证和审核，Agent 可能把错误模式写进长期规则。

边界：
我会先写七条：目标可验收、反馈有证据、连续失败暂停、敏感动作人审、更新可 diff、规则可回滚、高风险判断保留不确定性。

方法：
每次 Skill 更新，都要过一张审核表：为什么改、证据是什么、影响哪些任务、怎么回滚。

收束：
Agent 可以执行和复盘，但长期规则要由人把关。
```

镜头建议：用 7 条边界清单做字幕节奏。

### 抖音视频

标题：Agent 越自动，越要先写停止条件

脚本：

```text
开头：
Agent 越自动，越要先问：它什么时候停？

判断：
没有停止条件的自动化，很容易把小错误放大。

例子：
连续两轮同样失败、需要生产权限、diff 超范围、没有测试结果，这些都应该暂停。

行动：
给每个 Agent 任务写三句话：目标是什么，怎么验收，什么情况必须交还给人。

收束：
能停下来的 Agent，才更值得长期使用。
```

镜头建议：以“什么时候停？”作为整条视频视觉主轴。

## 06 EvoSkill 实测

### 小红书视频

标题：这个工具能不能真让 Agent 越用越聪明

脚本：

```text
开头：
我准备测一个问题：Agent 的失败轨迹，能不能自动变成 Skill？

判断：
这个方向很有价值，但要看三件事。

检查：
第一，提炼出的规则准不准。第二，会不会只适合这一次失败。第三，换一个相近任务还能不能用。

方法：
我会先选低风险任务，保留完整输入、输出和人工审核记录，再决定是否接入个人系统。

收束：
如果你想看完整测试，评论区留“EvoSkill”。
```

镜头建议：展示工具运行流程，不展示未核验指标大字报。

### 抖音视频

标题：Agent 失败后，能不能自动学会

脚本：

```text
开头：
Agent 失败一次，能不能自动长一个技能？

判断：
这个问题不能靠宣传回答，要靠实测。

例子：
如果工具能从失败日志里提炼出一条稳定规则，并且下次真的少犯同类错误，它就有价值。

行动：
测试时看三项：准确、不过拟合、能迁移。任何自动生成的 Skill 仍然要人审。

收束：
失败能不能变资产，这是我最想测的点。
```

镜头建议：用“失败日志 -> Skill -> 下次任务”的流程箭头。
