# 05 自改进 Agent 的边界：没有验证，它只是在漂移

状态：brief 完成，待采证后起稿
目标平台：微信公众号主发，小红书图文/视频和抖音拆条

## 文章功能

第五篇负责收束边界和 Human3.0 主线。它要告诉读者：自改进最难的部分，是知道什么不能改、什么时候停。

## 核心论点

没有验证和审核的自改进，会把错误模式沉淀成长期规则。

## 正文骨架

1. 开头：最危险的 Agent，是看起来一直在努力。
2. 漂移的三种来源：
   - 目标漂移。
   - 反馈漂移。
   - 规则漂移。
3. 7 条安全边界：
   - 目标必须可验收。
   - 反馈必须有证据。
   - 连续失败要暂停。
   - 生产敏感动作必须人审。
   - Skill 更新必须可 diff。
   - 每次合并必须可回滚。
   - 高风险结论必须保留不确定性。
4. Skill 更新审核表怎么用。
5. 人的位置：设边界、审规则、决定长期方向。
6. 第一季收束：自改进 Agent 是个人系统的一部分。

## 不写

- 不写恐吓式风险。
- 不把安全边界讲成阻碍效率。
