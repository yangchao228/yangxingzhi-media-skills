## 3. 审核问题

### 目标是否清楚

- [ ] 解决的是重复问题，不是一次性问题。
- [ ] 规则能被 Agent 执行。
- [ ] 规则没有把临时偏好写成长期偏好。

### 证据是否足够

- [ ] 有日志、测试、diff、来源链接或人工批注。
- [ ] 能说明这是同类失败，而不是孤立样本。
- [ ] 有反例或适用边界。

### 风险是否可控

- [ ] 不涉及密钥、隐私、生产配置、支付、删除等高风险动作。
- [ ] 不会扩大 Agent 权限。
- [ ] 不会让 Agent 绕过验证。
- [ ] 不会降低事实核验要求。
- [ ] 不会替用户做价值判断。

### 维护成本是否合理

- [ ] 新规则不会让 Skill 变得过长。
- [ ] 与现有规则不冲突。
- [ ] 能被未来任务复用。
- [ ] 有明确回滚方式。

```text
请基于反馈日志生成 Skill 更新建议，但不要直接修改文件。

每条建议必须包含：
1. 想解决的重复失败。
2. 证据位置。
3. 建议写入的规则文本。
4. 适用范围和不适用范围。
5. 潜在风险。
6. 回滚方式。

如果证据不足，请输出 defer，不要强行生成规则。
```
