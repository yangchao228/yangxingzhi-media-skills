# Agent 反馈日志模板

用途：记录 Agent 在真实任务中的失败、纠偏和下一次可复用规则。适合内容生产、代码排障、项目巡检、资料整理等可验证任务。

## 使用原则

- 每条记录只对应一次明确任务。
- 必须写验证证据，不只写主观感受。
- 只有重复出现或影响较大的失败，才进入 Skill 更新候选。
- 临时偏好、一次性情绪、未核实事实，不写入长期规则。

### 4. 失败归因

- [ ] 目标描述不清
- [ ] 缺少验收标准

- [ ] 忽略了已有约定

- [ ] 没有执行验证

### 5. 下一次规则

写成 Agent 能执行的规则，避免空泛提醒。

差的写法：

```text
下次注意不要出错。
```

好的写法：

```text
处理中文路径文件前，先用 find 或 ls -lb 确认真实文件名，再引用路径。
```

## 外环 Agent 复盘提示词

```text
请读取本周 Agent 反馈日志，只做三件事：
1. 找出重复出现的失败模式。
2. 判断哪些失败值得更新为 Skill、模板或检查清单。
3. 为每个候选更新生成简短 diff 建议，并说明证据、收益、风险和回滚方式。

不要自动修改文件。涉及发布、删除、密钥、生产配置、支付、个人隐私、价值判断的内容，必须标记为需要人工确认。
```
