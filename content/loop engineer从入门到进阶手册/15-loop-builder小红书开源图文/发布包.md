# loop-builder 小红书开源图文发布包

## 1. 内容诊断

- 核心主题：开源项目 `loop-builder` 帮助用户把一句模糊任务整理成可控 Agent Loop。
- 最强传播角度：用户不需要先懂 Loop，只需要先说出真实任务。
- 目标受众：使用 Codex、Cursor、Claude Code 或其他 Agent 工作流，经常反复补提示词的人。
- 封面结果点：`提示词越补越乱？给任务搭个 Loop。`
- 推荐风格：贴纸轻科技风。适合 AI 工具、Agent 工作流、独立开发与开源项目传播。
- 推荐页数：8 张。项目机制、产物选择、两个代表场景、仓库资产和 GitHub CTA 都需要独立页面，8 张能保持手机端阅读舒适度。
- 证据边界：CI 是典型落地场景；UI 精准复刻是有前后截图的真实跑通案例。

## 3. 逐页文案与呈现

### 01 / 封面

- 页面标题：`提示词越补越乱？给任务搭个 Loop`
- 副标题：`把临时对话沉淀成可验证、可复用的执行资产。`
- 关键词：提示词、Loop、开源。
- 视觉元素：项目 Logo、开源圆形贴纸、五阶段简化流程。
- 呈现形式：大标题占据上半区，流程卡位于下半区。

### 02 / 用户痛点

- 页面标题：`反复补提示词，任务还是容易失控`
- 正文：目标越改越散、缺少证据只能猜、每轮改动太多、经验无法复用。
- 结论：`任务需要进入一个可验证、可停止的闭环。`
- 呈现形式：2×2 问题卡片。

### 03 / 项目机制

- 页面标题：`loop-builder 先替你接住复杂性`
- 流程：一句自然语言、上下文闸门、产物选择、反馈与停止、可复用资产。
- 边界：`缺少关键证据时暂停；正式执行逻辑先交给人确认。`
- 呈现形式：五段纵向流程与人工确认提示条。

### 04 / 产物选择

- 页面标题：`先选最轻方案，再逐级升级`
- 产物：Prompt、Checklist、Human-in-the-Loop、Loop 脚手架、Agent 包、专用 Skill。
- 结论：`一次性任务不会被强行包装成完整 Loop。`
- 呈现形式：2×3 选择矩阵。

### 05 / CI 自动修复

- 标签：`典型落地场景 · CI`
- 页面标题：`CI 修复为什么适合做成 Loop`
- 流程：失败日志、Planner 定位、Maker 最小修复、Checker 测试与审 diff、Evaluator 继续或停止。
- 反馈：test、lint、build、git diff。
- 警戒条：`不削弱测试，不做无关重构，不自动 merge；最终 diff 等待人工确认。`
- 呈现形式：真实 CI 巡检流程图与反馈标签。

### 06 / UI 精准复刻

- 标签：`真实跑通案例 · UI`
- 页面标题：`页面能跑以后，怎么继续逼近目标图`
- 三阶段：目标稿、第一版、最终版。
- Top 3：日期卡片、字体字重、文字颜色。
- 结论：`目标图 → 当前截图 → Top 3 差异 → 修正 → 再截图。`
- 边界：最终审美判断、提交和发布继续由人完成。
- 呈现形式：三列真实截图对比。

### 07 / 开源仓库内容

- 页面标题：`仓库里已经准备好这些可复用资产`
- 资产：主 Skill、中英文说明、Prompt、Checklist、Loop 协议、Agent/Skill、验证记录、MIT License。
- 事实说明：`仓库当前提供 Codex Skill 形态；核心方法可以迁移到其他 Agent 工作流。`
- 呈现形式：2×4 资产卡片。

### 08 / GitHub 行动

- 页面标题：`拿你的任务，先跑一次`
- 最小输入：`请使用 $loop-builder，把这个反复出现的任务做成一个可控 Agent Loop。`
- 地址：`github.com/yangchao228/loop-builder`
- CTA：`访问仓库，先跑一次，再决定是否沉淀成长期 Skill。`
- 呈现形式：深色行动卡、Prompt、二维码、可抄写地址。

## 4. 统一视觉规范

- 风格模式：贴纸轻科技风。
- 尺寸：1080×1440，3:4 竖版。
- 主色：深蓝 `#071A3B`、钴蓝 `#2457E6`、青绿 `#0D918B`。
- 风险色：橙色 `#F28C28`，只用于停止规则、风险和人工确认。
- 背景：白色到浅蓝渐变，叠加低对比网格。
- 字体：PingFang SC 优先；主标题 65—91px，正文不低于 19px。
- 固定组件：左上 loop-builder 品牌、右上页码、底部 `LOOP ENGINEERING` 与 `AI生命克劳德`。
- 版式规则：每页一个判断；主标题左对齐；列表和矩阵使用大间距卡片；真实截图不加复杂滤镜。
- 硬约束：不出现机器人、真人、装饰性小字、长代码截图和动态 Star 数。

### 主发布配文

我最近把自己用来设计 Agent Loop 的方法整理成了开源项目 `loop-builder`。

你只需要用一句自然语言描述任务，它会先检查目标、证据和边界，再判断当前适合 Prompt、Checklist、Human-in-the-Loop、完整 Loop、Agent 包还是专用 Skill。

图里放了两个代表场景：CI 修复通过测试、lint 和 diff 形成反馈闭环；UI 复刻通过目标图、当前截图和 Top 3 差异持续收敛。

当前仓库提供 Codex Skill 形态，核心方法可以迁移到其他 Agent 工作流。第 8 张有 GitHub 地址和二维码，找一个反复出现的任务先跑一次。

### 口语短配文

我把自己搭 Agent Loop 的方法开源了。

一句话描述任务，`loop-builder` 会帮你补齐目标、证据、反馈和停止规则，再选择最合适的 Prompt、Checklist、Loop、Agent 或 Skill。

图里放了 CI 修复和 UI 复刻两个场景。仓库地址和二维码在第 8 张，拿一个你经常重复做的任务试一次。
