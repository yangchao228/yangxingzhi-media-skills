## 标准流程

1. 先确定配图是否必要。
   - 适合配图：总览清单、流程结构、边界关系、决策表、模板结构、风险清单。
   - 谨慎配图：纯观点段、情绪段、过渡段。

2. 先定插图位置。
   - 开头价值承诺后：放总览图。
   - 长模板或代码块前：放结构图。
   - 风险动作或人工确认前：放边界图。

3. 再写提示词包。
   - 每张图固定包含：图片用途、插入位置、画面结构、中文文案、风格要求、负面提示词、完整提示词。
   - 中文文案先在 Markdown 中定稿，再复制进提示词。
   - 每张图文字控制在 10 到 18 个短语以内。

4. 先生成 1 张样图。
   - 优先生成风险边界图或总览图。
   - 检查中文准确性、手机端可读性、系列风格统一性。
   - 合格后再继续生成剩余图片。

5. 保存到项目目录。
   - 内置 `image_gen` 默认保存在 `$CODEX_HOME/generated_images/...`。
   - 项目会引用的图片必须复制到当前系列目录。
   - 文件命名建议：`08-1-断路器总览图.png`、`08-2-TODO状态文件结构图.png`、`08-3-人机确认边界样图.png`。

6. 在正文标注插图位。
   - 已生成的图可以直接用 Markdown 图片语法引用。
   - 未生成的图先用可见提示块标注，发布前再替换。

7. 发布前再处理图床。
   - 需要远程链接时，使用 `md-img-r2`。
   - 上传前确认图片不是草稿、样图或带错误中文的版本。

## Loop Engineering 系列视觉基线

- 画幅：竖版 1080x1440 或接近 3:4。
- 背景：深蓝黑，细网格，电路纹理，控制台感。
- 主色：蓝青色。
- 风险色：橙红色，只用于停止、危险、人工确认。
- 字体：粗、清晰、强对比，手机端可读。
- 信息密度：宁可少字，也不要小字堆叠。
- 品牌署名：`AI生命克劳德`，放底部小字号。

## 通用提示词骨架

```text
Use case: infographic-diagram
Asset type: 微信公众号正文信息图，竖版 1080x1440
Primary request: 生成一张「主题」信息图，用于解释「读者要理解的核心关系」。
Scene/backdrop: 深蓝黑科技背景，细网格、电路纹理，背景克制，不抢文字。
Subject: 描述主体结构，例如 2 列卡片、中心节点、左右分栏、流程图。
Style/medium: 高质量中文信息图，科技感，清晰排版，公众号手机端可读。
Composition/framing: 顶部标题，中间主体，底部总结。留足边距。
Lighting/mood: 冷静、专业、可控。
Color palette: 深蓝黑、霓虹蓝、青色、白色文字，少量橙红色风险提示。
Text (verbatim): "逐字列出全部中文"
Constraints: 所有中文必须逐字准确；只出现上述文字；手机端可读；不要添加额外说明。
Avoid: 复杂小字、乱码中文、拼写错误、英文乱入、额外标签、随机水印、摄影人物、过度赛博朋克、紫色渐变、米色背景、花哨装饰、3D 卡通角色、密集流程线、低对比度文字。
```

## 质量检查清单

- 中文是否逐字准确。
- 标题、模块、底部总结是否层级清楚。
- 手机端缩小后是否还能读主标题和模块标题。
- 是否出现多余英文、乱码、随机 logo 或水印。
- 风险动作是否使用橙红色，普通信息是否使用蓝青色。
- 是否和系列已有 02、03、04 篇图片风格一致。
- 图片是否已复制到项目目录。
- 正文引用路径是否正确。
- 是否误写工具能力，或让 Agent 自行执行发布、上架等高风险动作。

## 何时用哪种能力

- 只需要正文配图：用 `image_gen` 生成样图和最终图。
- 需要成组图文卡片：用 `wechat-to-cards` 或 `long-to-cards`。
- 需要小红书成套图片：用 `xiaohongshu-viral-image-set-generator-v4`。
- 需要上传 Markdown 本地图片：用 `md-img-r2`。
- 需要探索多种商业视觉方向：再考虑 Creative Production 插件。
