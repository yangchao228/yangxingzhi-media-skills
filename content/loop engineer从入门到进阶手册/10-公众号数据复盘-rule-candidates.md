## 候选通用规则

### 候选规则 1：内容数据复盘先诊断，再升级长期 Loop

- 规则：内容数据复盘类任务，适合先用 Explore-Narrow 做只读诊断，再决定是否升级为 Lifecycle Loop。
- 来源任务：公众号数据复盘 Loop Agent 第 1 轮。
- 触发次数：1。
- 支撑证据：5 篇文章数据足以做选题诊断，但还不足以证明长期周期化稳定有效。
- 适用边界：公众号、知乎、小红书、newsletter 等内容数据复盘。
- 反例：如果已经有稳定周报流程和多轮历史数据，可以直接进入 Lifecycle Loop。
- 建议：暂存，不升级 `loop-builder`。

### 候选规则 2：专用 Agent 首轮先验证决策价值

- 规则：专用 Agent 首轮运行后，应优先验证“是否帮用户做出具体决策”，而不是继续扩展文件和流程。
- 来源任务：公众号数据复盘 Loop Agent 第 1 轮。
- 触发次数：1。
- 支撑证据：本轮产出第 6 篇选题排序、验证指标和暂停条件，比继续增加 Agent 文件更有价值。
- 适用边界：新生成的任务专属 Loop Agent。
- 反例：如果 Agent 用于合规、生产、财务等高风险任务，首轮可能需要先补审计和权限规则。
- 建议：暂存，不升级 `loop-builder`。
