## 项目目标

把已经发布的 5 篇公众号系列和旧素材汇编，整理成一本可继续打磨、可上架、可拆分分发的电子书母稿。

这本书不做公众号合集。它要完成三件事：

- 把 Loop Engineering 的概念、结构、模式、角色和实操重新组织成书稿。
- 补足公众号文章之间缺少的过渡、模板、决策表、失败案例和成本边界。
- 沉淀一套可复用资产：模板包、Prompt 包、清单、发布包和后续扩展选题。

## 成书原则

1. 先定书稿结构，再写正文。
2. 每章都要有读者收获，不能只转述概念。
3. 工具命令必须有边界，不能把未经验证的命令写成教程。
4. Codex、Claude Code、Cursor、自建 Agent 分清楚，不混成一套能力。
5. 保留人的判断权：merge、权限、生产配置、数据删除、售卖上架都需要人工确认。
6. 默认归档：适合沉淀的章节、模板、案例和表格默认进入 Human3.0 素材库，除非用户明确撤销。

## 风险清单

| 风险 | 影响 | 处理方式 |
|---|---|---|
| 公众号语境残留 | 读起来像合集，不像书 | 删除“第几篇”“下一篇预告”“评论区”等表达 |
| 重复解释 Loop | 篇幅膨胀 | 合并为“定义 / 结构 / 模式 / 实操”四层 |
| 旧素材汇编含旧工具命令 | 事实风险 | 只吸收结构，不直接复用命令 |
| Codex 和 Claude Code 混写 | 读者照做会出错 | Codex 实操独立成章，Claude Code 放扩展方向 |
| 模板不足 | 电子书增量不够 | 附录集中补模板包 |
| 成本边界不清 | 容易误导读者 | 单独写成本、停止规则和断路器 |
