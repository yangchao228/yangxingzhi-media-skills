Loop 不是单个提示词，而是一套可触发、可检查、可交接的运行结构。
Skill vs Memory：能力沉淀和状态沉淀要分开
Skill 保存稳定规则，Memory 保存当前进展
Skill

长期稳定的做法

  • 怎么写、怎么查、怎么验收
  • 适合跨项目复用
  • 应该少变、可审查
规则
vs
状态
Memory

这一轮任务的进展

  • 做到哪里、还有什么阻塞
  • 适合跨轮次延续
  • 应该及时更新、避免过期
Skill 和 Memory 混在一起，Loop 很容易被旧状态污染。

Loop 模式怎么选
把任务特征显性化，再决定是否循环
Step 1

任务会重复发生吗？

否：继续用 Prompt

Step 2

反馈信号清楚吗？

否：先补 Checker

Step 3

风险是否可控？

否：加入人工确认

Step 4

是否需要长期状态？

是：加入 Memory

Step 5

是否需要多角色？

是：拆三角色

Decision

选择主模式

Review / Repair / Research / Monitor / Delivery

Human

必须人工确认

  • 生产发布和外部提交
  • 权限、资金和敏感数据
  • 高风险改动和不可逆操作
  • 价值判断和最终取舍
好的 Loop 会把证据推到人面前，而不是替人做最终判断。
