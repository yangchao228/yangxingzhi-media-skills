## 四、每篇文章的可复用内容

### 第 1 篇：范式变化

可复用：

- Prompt -> Context -> Harness -> Loop 的四层演进。
- Loop 不等于 Cron Job。
- 人的角色从写提示词转向设计循环系统。
- 自动化越强，人的验收和停止规则越重要。

需要改写：

- 公众号开头中的热点感和发布时间语境。
- “第几篇”“下一篇”等连载语气。
- 外部人物和社区反应需要降低成背景材料，书稿主线要回到读者的问题。

### 第 2 篇：六块积木

可复用：

- Automations 是心跳。
- Worktrees 是隔离层。
- Skills 是知识沉淀。
- Connectors 是工具入口。
- Sub-agents 是角色拆分。
- Memory 是模型外部状态。
- 六块积木的最小装配顺序。

需要补充：

- 六块积木不是同一层级：有的是基础设施，有的是协作约束，有的是状态系统。
- 每块积木都要补“最小可用版本”和“常见误用”。

### 第 3 篇：五种模式

可复用：

- Retry Loop。
- Plan-Execute-Verify。
- Explore-Narrow。
- Human-in-the-Loop。
- Lifecycle Loop。
- 决策表。
- 复杂项目模式组合。

需要补充：

- 每种模式加一个“适用 / 不适用”表。
- 加“选错模式会发生什么”。
- 把公众号末尾预告删掉，改成书稿过渡。

### 第 4 篇：三角色架构

可复用：

- Agent 自审不可靠。
- Context Anxiety 和 Self-Evaluation Bias。
- Planner / Generator / Evaluator 三角色。
- Evaluator 的评分标准。
- Maker + Checker 是最小可落地版本。

需要补充：

- Harness 的定义和边界。
- 三角色如何与第 3 章的 5 种模式组合。
- 前端设计案例与软件开发案例要区分，不要混成一类。

### 第 5 篇：Codex 实操

可复用：

- 前置条件。
- `TODO.md` state file。
- 只读侦察。
- Maker 最小修复。
- Checker 独立验收。
- 最小闭环案例。
- 断路器。
- 成本管控。
- 本地实测发现的 Codex 环境问题和 token 成本边界。

需要补充：

- 把公众号结尾的评论区征集移到发布包，不进主稿。
- 把“30 分钟执行清单”升级成附录模板。
- 补一段“为什么第一个 Loop 不应该自动 merge”。

## 五、旧素材汇编的处理

旧素材汇编价值：

- 有完整的 8 章骨架。
- 有术语表、资源清单、命令速查表、Loop 模板。
- 有 Anthropic 三角色素材补充。

旧素材汇编风险：

- 标题叫“实战手册”，但旧版本实操比例不足。
- 部分 Claude Code / Codex 命令边界已经过时或未经本地验证。
- 含 `PIV Loop`、`Codex 持久目标 (CLI 0.128.0+)` 等需要重新核实的说法。
- 有重复标题和公众号遗留痕迹。

使用策略：

- 吸收旧目录的“概念层 / 架构层 / 模式层 / 实操层 / 避坑层 / 进阶层 / 哲学层”。
- 删除未经验证的命令。
- 把“工具层对照”改成“扩展方向”，避免读者照着执行错误命令。
- 术语表和资源清单进入附录，但需要重新审查。

## 七、事实边界

当前可确认：

- 本地 `codex-cli 0.139.0` 的核心命令包含 `codex exec`。
- 第 5 篇的最小 CI 修复 Loop 已用临时项目跑通过。
- 电子书主实操路径应以 Codex CLI 为主。

## 八、成书判断

这套素材已经具备成书条件。

它的价值不在“讲了一个新名词”，而在于把 AI Agent 自动化从概念拆成了：

- 结构：Loop 靠什么跑。
- 模式：不同任务怎么选。
- 角色：谁规划、谁生成、谁验收。
- 实操：如何跑通第一个 Codex CI 修复 Loop。
- 边界：成本、停止规则、人的判断权。
