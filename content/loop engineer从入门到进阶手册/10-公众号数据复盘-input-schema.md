# 公众号数据复盘输入 Schema

## 目标

为 `公众号数据复盘 Loop Agent` 提供稳定输入格式，便于每次发布后追加数据并复盘。

## 必填字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 篇目 | 文本 | 系列序号，例如第1篇 |
| 标题 | 文本 | 实际发布标题 |
| 发布日期 | 日期 | 文章发布日期 |
| 阅读 | 数字 | 后台阅读人数 |
| 平均阅读时长 | 数字 | 单位：分钟 |
| 完读率 | 百分比 | 后台完读率 |
| 新增关注 | 数字 | 文章带来的新增关注 |
| 分享 | 数字 | 分享人数 |
| 喜欢 | 数字 | 后台心形互动数 |
| 点赞 | 数字 | 后台点赞数 |
| 留言 | 数字 | 留言条数 |
| 收藏 | 数字 | 收藏人数 |

## 可选字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 文章类型 | 文本 | 热点观点 / 基础框架 / 模式决策 / 架构拆解 / 实战案例 / 避坑清单 |
| 标题版本 | 文本 | 如发布前有多个标题，可记录最终选择 |
| 封面版本 | 文本 | 可记录封面图文件 |
| 朋友圈反馈 | 文本 | 只记录真实反馈，不补写推测 |
| 私聊反馈 | 文本 | 只记录真实问题或原话摘要 |
| 是否收入电子书 | 文本 | 待确认 / 是 / 否 |
| 备注 | 文本 | 数据来源、更新时间或特殊情况 |

## 派生指标

每轮复盘可以计算，但不要写入原始数据表作为事实来源：

| 指标 | 公式 | 用途 |
| --- | --- | --- |
| 分享率 | 分享 / 阅读 | 判断转发价值 |
| 收藏率 | 收藏 / 阅读 | 判断工具性和长期价值 |
| 关注率 | 新增关注 / 阅读 | 判断拉新能力 |
| 点赞率 | 点赞 / 阅读 | 判断显性认可 |
| 互动率 | (分享 + 喜欢 + 点赞 + 留言 + 收藏) / 阅读 | 判断综合互动 |

## 数据边界

- 后台数据可以用于选题判断，但不能单独证明内容质量。
- 单篇数据不能直接抽象成通用规则。
- 缺少留言时，不要推断具体读者需求。
- 发布、入书、投稿和商业化必须由用户确认。
