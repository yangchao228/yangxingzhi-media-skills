# Loop Engineering 专题资产 Loop 示例

## 用户输入

```md
请使用 loop-builder，把 Loop Engineering 专题后续建设做成一个长期内容资产 Loop。

任务目标：
把已发布的公众号系列、电子书主稿、读者反馈和后续选题，沉淀为可持续更新的内容资产系统。

输入材料：
- `content/loop engineer从入门到进阶手册/`
- `content/loop engineer从入门到进阶手册/book-v1/`
- 已发布公众号文章反馈
- 后续选题想法

成功标准：
- 能持续产出公众号文章、电子书增补材料、案例库和可复用模板。
- 每一轮都有状态记录、选题判断、素材归档和人工确认节点。

允许修改：
- 专题目录下的草稿、素材、任务板和说明文件。

必须人工确认：
- 公众号发布。
- 微信读书投稿。
- 电子书商业上架。
- 读者反馈是否进入正文。
```

## 推荐模式

- 主模式：Lifecycle Loop。
- 可组合模式：Explore-Narrow、Human-in-the-Loop。

理由：

- 这是长期专题，不是一次性交付。
- 每轮需要读取上轮状态、读者反馈和素材库。
- 选题和商业发布需要人判断。

## 最小 Loop 设计卡

| 字段 | 内容 |
|---|---|
| 目标 | 把 Loop Engineering 专题沉淀为持续更新的内容资产系统 |
| 输入 | 已发布文章、电子书主稿、读者反馈、案例素材、工具实践记录 |
| 状态 | `content/loop engineer从入门到进阶手册/06-Loop Engineering 后续内容生产 Loop.md` |
| 执行者 | Topic Scout / Research Maker / Draft Maker / Review Checker / Archive Evaluator |
| 验收者 | 用户 + 文昌诊文 + 发布检查 |
| 反馈信号 | 阅读反馈、留言问题、案例完整度、事实来源、草稿质量、投稿适配度 |
| 停止规则 | 证据不足、读者获得感不清、成本超限、需要发布或投稿确认 |
| 人工确认节点 | 选题、标题、公众号发布、投稿、商业上架、读者反馈入正文 |
| 禁止动作 | 不替用户发布，不替用户投稿，不编造读者反馈，不把未验证工具能力写成事实 |

## 推荐阶段

| 阶段 | 目标 | 产物 |
| --- | --- | --- |
| 反馈收集 | 从留言、私信、阅读数据中提取真实问题 | 反馈表 |
| 选题收敛 | 选择下一篇或下一章最值得补的内容 | 选题决策表 |
| 案例补证 | 补真实操作、失败案例和成本记录 | 案例卡 |
| 起稿修订 | 生成公众号稿或电子书增补章节 | 草稿 |
| 诊文出刊 | 做发布前质量检查 | 诊断报告、发布包 |
| 归档入书 | 判断是否进入电子书 v1.x | 素材归档记录 |

## 本场景断路器

- 没有真实读者问题时，不进入长文写作。
- 没有可验证实践时，不写“实战手册”。
- 未确认发布前，不生成最终发布动作。
- 工具能力只要存在不确定性，就写成“待验证”或“扩展方向”。
