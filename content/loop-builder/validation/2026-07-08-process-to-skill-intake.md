# loop-builder 过程沉淀入口验证

日期：2026-07-08

## 背景

用户希望用低成本入口把刚才跑通的真实过程沉淀成 Skill / Loop / Agent。`loop-builder` 不能要求用户重新填写完整材料清单。

## 规则

- 用户说“把刚才 / 这次 / 上一轮过程沉淀成 Skill / Loop / Agent”时，默认进入过程沉淀入口。
- 先从当前对话、项目证据、截图路径、diff、TODO、state、run log 和测试结果中自动抽取真实样本。
- 抽取后再执行决策依赖 Gate。
- 只有缺失会影响复杂度、最大轮次、风险、执行策略或 Skill 输入契约的关键证据时，才输出 `WAITING_FOR_CONTEXT`。
- 补问只问缺失关键证据，并给 2-5 个最小样本示例。
- 禁止一上来要求用户填写完整复盘表。

## 用例一：上下文充足

用户输入：

```md
请使用 loop-builder，把刚才这次 UI 复刻过程沉淀成一个可复用 Skill。
```

上下文中已有目标图、初始截图、最终截图、轮次记录和差异清单。

期望行为：

- 自动抽取上述证据。
- 输出 `WAITING_FOR_LOGIC_CONFIRMATION`。
- 输出过程沉淀自动抽取摘要、决策依赖检查、任务卡和工作逻辑确认卡。
- 不要求用户重新填写完整材料清单。
- 不直接写 Skill 文件。

## 用例二：关键证据缺失

用户输入：

```md
把刚才过程沉淀成 Skill。
```

上下文缺少最终结果和每轮反馈信号。

期望行为：

- 输出 `WAITING_FOR_CONTEXT`。
- 只补问最终结果和每轮反馈信号。
- 给出最小样本示例，例如最终截图、测试结果、差异清单或验收结论。
- 不要求用户补完整复盘表。

## 用例三：非 UI 场景

用户输入：

```md
把刚才修 CI 的过程沉淀成 Skill。
```

期望行为：

- 不套用 UI 字段。
- 动态抽取失败日志、测试命令、修复步骤、最终测试结果和禁止动作。
- 缺少关键证据时只补问对应证据。
