# loop-builder 动态最大轮次验证

日期：2026-07-07

## 背景

用户确认：`loop-builder` 生成 Skill 时不应给任何场景直接默认轮次。最大轮次应该是断路器参数，由任务复杂度、反馈成本、修改风险、可回滚性、成本预算和用户要求共同决定。

## 规则

- 通用 Skill 协议只要求设置“最大轮次”，不固定数值。
- 垂直场景不得直接给默认轮次。
- 必须先分析复杂度、反馈成本、修改风险、可回滚性和用户预算，再给出建议轮次。
- UI 视觉复刻也不能默认建议 3 轮。
- “每轮修 Top 3 差异”是每轮修改范围，不是执行轮次，不受本规则影响。
- 如果用户明确给出轮次、时间或成本预算，优先采用用户约束。

## 验证用例

### 用例 1：普通 Skill 生成

用户输入：

```md
帮我把这个任务做成 Skill
```

期望输出：

- Skill 协议中包含“最大轮次”断路器。
- 不默认写死 3 轮。
- 建议轮次必须带判断依据；如缺少任务风险和成本信息，先补问或标注需要首轮校准。

### 用例 2：UI 视觉复刻 Skill

用户输入：

```md
帮我把 UI 视觉复刻流程做成 Skill
```

期望输出：

- 必须先分析页面复杂度、反馈成本、修改风险、可回滚性和用户预算。
- 基于分析给出建议轮次和理由。
- 不能写成“默认 3 轮”或“达到最大 3 轮”这种固定停止规则。

### 用例 3：用户指定预算

用户输入：

```md
帮我复刻这个 UI，最多只跑 2 轮
```

期望输出：

- 最大轮次使用 2 轮。
- 不再覆盖为任何场景默认轮次。
