# loop-builder 决策依赖 Gate 验证

日期：2026-07-08

## 背景

`loop-builder` 不能只根据任务类型判断信息是否足够。它必须先判断本轮要产出哪些关键结论，再判断这些结论依赖哪些证据。

## 规则

- Context Gate 之后、任务卡之前，必须执行决策依赖 Gate。
- 决策依赖由本轮关键判断动态推导，不能把某个场景字段硬编码成所有任务的必填项。
- 构建 Loop 默认要基于当前具体任务判断复杂度、最大轮次、风险和执行策略。
- 如果用户要求基于具体任务、样本、材料、故障或运行情况判断复杂度、最大轮次、风险或执行策略，相关样本就是必需输入。
- 缺少必需决策依赖时，输出 `WAITING_FOR_CONTEXT` 并 hard stop。
- 只有用户明确要求通用框架、通用协议、通用模板，或明确接受先不基于真实样本校准时，才可以继续，但必须标注“未基于真实样本校准”。
- 工作逻辑确认卡必须包含输入边界：构建期输入、运行期输入、复杂度校准输入。

## 用例一：具体任务校准

用户输入：

```md
帮我把这个任务做成 Loop。
```

但用户没有提供具体样本、材料、日志、数据或目标物。

期望行为：

- 输出开头标注 `WAITING_FOR_CONTEXT`。
- 说明构建 Loop 默认需要“用于判断复杂度、最大轮次、风险和执行策略的任务样本或证据”。
- 给出 2-5 个当前任务可接受的最小样本示例，帮助用户补材料。
- 不输出任务卡、Loop 适配判断、自动产物选择或工作逻辑确认卡。
- 不用模型猜测复杂度和轮次。

## 用例二：通用模板

用户输入：

```md
帮我设计一个通用的任务复盘 Loop 模板。
```

用户没有提供具体复盘样本。

期望行为：

- 可以进入 `WAITING_FOR_LOGIC_CONFIRMATION`。
- 确认卡必须标注“未基于真实样本校准”。
- 复杂度、轮次和风险只能给通用区间或默认规则。
- 未来运行期输入必须单独列出。

## 用例三：构建期和运行期分离

用户输入：

```md
帮我生成一个跨项目复用的专用 Skill。
```

期望行为：

- 先判断本轮是否需要真实样本校准。
- 如果要基于真实案例推导工作流、复杂度或最大轮次，样本是必需输入。
- 如果只生成通用协议草案，可以继续，但确认卡必须区分：
  - 构建期输入。
  - 未来运行期输入。
  - 复杂度校准输入。
