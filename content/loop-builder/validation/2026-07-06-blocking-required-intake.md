# loop-builder 阻塞式补问验证

日期：2026-07-06

## 背景

用户希望执行 `loop-builder` 时，如果存在真正缺失的必需用户上下文，系统先停下来提问，等用户回复后再继续，而不是一边缺信息一边生成 Prompt、Loop 包或 Skill 协议。

## 规则

- 所有任务先过 Context Gate，再进入场景流程。
- 缺失信息先分成：必需、可默认、后置确认。
- 必需信息缺失时必须全部补问，不限制数量。
- 只要存在缺失必需上下文，本轮必须停止在补问状态。
- 停止状态下只能输出补问卡，不得生成任务卡、Loop 适配判断、自动产物选择、最终 Prompt、Skill 化建议、Skill 协议、Loop 包或写文件。
- 用户回复后，合并新信息并重新进入 Context Gate 判断。
- 可默认信息最多展示 5 个默认处理方式，不作为强制输入。
- 后置确认留到执行中触发风险时再问。

## 用例 1：UI 复刻缺少目标图

用户输入：

```md
帮我复刻这个 UI 视觉稿
```

如果没有附图或本地路径，期望输出：

- 自动识别 UI 视觉复刻场景。
- 判断目标图是必需信息。
- 只请求用户补充目标图。
- 不输出任务卡。
- 不输出 Skill 化建议。
- 不生成 UI 复刻 Prompt。
- 不生成 Skill 协议。
- 不写文件。

## 用例 2：UI 复刻已有目标图

用户输入：

```md
帮我复刻这个 UI 视觉稿
目标图：/tmp/design.png
```

期望输出：

- 不追问页面入口、技术栈、修改范围。
- 页面入口作为只读侦察默认项。
- 修改范围作为执行边界和后置确认。
- 直接生成可复制给 Codex 的 UI 复刻 Prompt。

## 用例 3：CI 修复缺少失败日志

用户输入：

```md
帮我修这个 CI
```

如果没有失败日志、检查链接或可运行的本地测试命令，期望输出：

- 判断失败反馈是必需上下文。
- 只请求用户补充失败日志、CI 链接或可复现命令。
- 不生成 CI 修复 Prompt 或 Loop 包。

## 用例 4：内容复盘缺少数据

用户输入：

```md
帮我复盘这组公众号文章，继续选题
```

如果没有文章列表、阅读数据或反馈材料，期望输出：

- 判断复盘样本和反馈信号是必需上下文。
- 只请求用户补充文章范围和可获得的数据。
- 不输出选题建议、任务卡或 Skill 化建议。

## 用例 5：生成专用 Skill 缺少复用场景

用户输入：

```md
帮我把这个任务做成 Skill
```

如果没有任务类型、复用场景和输入材料，期望输出：

- 判断复用场景和输入契约是必需上下文。
- 只请求用户补充这些信息。
- 不生成 Skill 协议草案。

## 通过标准

- 必需问题会阻塞流程。
- 非必需问题不会阻塞流程。
- 补问后不会继续夹带最终产物。
- 用户回复后能继续原任务。
