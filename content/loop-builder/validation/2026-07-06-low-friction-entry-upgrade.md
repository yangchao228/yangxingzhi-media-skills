# loop-builder 低信息入口升级验证

日期：2026-07-06

## 背景

用户反馈：如果使用 `loop-builder` 还需要先复制长提示词、选择输出档位、声明生成 Skill，普通用户成本太高。

目标体验：

```md
帮我复刻这个 UI 视觉稿
```

`loop-builder` 应自动识别场景、补问必要信息、选择合适产物，并直接生成可拿去给 Codex 使用的 Prompt 或进一步的 Skill 方案。

补问不能来自固定问题清单。必须先判断缺失信息是“必需、可默认、后置确认”。缺失的必需信息必须全部补问，并且本轮停止等待用户回复；可默认信息最多展示 5 个默认处理方式，不能作为强制输入。

## 本次改动

- `SKILL.md` 增加低信息入口处理。
- `quick-start.md` 改为一句话入口。
- `skill-generation-contract.md` 增加过渡 Prompt 要求。
- `references/scenarios/ui-visual-match-loop.md` 增加 UI 复刻 Prompt 骨架。
- `skill.json` 更新为低信息入口定位。

## 验证用例

### 用例 1：一句话 UI 复刻

用户输入：

```md
帮我复刻这个 UI 视觉稿
```

期望行为：

- 自动识别为 UI 视觉复刻场景。
- 如果用户已上传图片或给出本地图片路径，不问前置问题，直接生成 Prompt。
- 如果模型判断没有可用目标图，目标视觉稿就是必需输入，需要请求用户补充。
- 请求用户补充目标图后 hard stop，不继续生成任务卡、UI 复刻 Prompt 或 Skill 化建议。
- 当前页面入口和允许修改范围不作为前置阻塞问题，应进入 Prompt 的默认侦察和边界规则。
- 页面入口、修改范围、技术栈属于可默认或后置确认信息，除非模型判断当前任务没有它们无法执行。
- 不要求用户写长提示词。
- 不要求用户先选择 Prompt / Skill。
- 不要求用户先确认页面入口或允许修改文件。
- 默认输出“给 Codex 使用的 UI 复刻 Loop Prompt”。
- Prompt 必须包含：
  - 高级前端还原工程师角色。
  - 先只读分析设计稿，不写代码。
  - 页面结构、组件树、tokens、字体、间距、圆角、阴影、资产分析。
  - 分阶段实现。
  - 截图反馈。
  - 每轮只修 Top 3 差异。
  - 禁止改业务逻辑、自动提交、自动发布。

### 用例 2：用户明确要跨项目复用

用户输入：

```md
这个 UI 复刻流程以后会在多个项目反复用，帮我做成全局 Skill。
```

期望行为：

- 进入专用 Skill 路线。
- 先输出场景工作流分析和 Skill 协议草案。
- 同时给出过渡 Prompt，便于先跑当前任务。
- 用户确认协议后，才生成 `SKILL.md` 和 `skill.json`。

### 用例 3：拼写错误

用户输入：

```md
使用 lopp-builder 帮我复刻这个 UI 视觉稿
```

期望行为：

- 识别为 `loop-builder` 意图。
- 不纠结拼写。
- 继续低信息入口流程。

## 通过标准

- 用户一句话能启动流程。
- 输出中有可复制给 Codex 的 Prompt。
- 不把用户推回复杂模板。
- 不默认生成 Skill。
- 需要长期复用时才升级为 Skill。
