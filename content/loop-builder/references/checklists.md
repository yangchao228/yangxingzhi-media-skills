# Loop 检查清单

本文件用于输出验收、断路器、成本控制、落地计划和复盘清单。

## 任务适配清单

进入 Loop 前，至少满足以下条件中的多数项：

- [ ] 目标能用一句话描述。
- [ ] 成功标准可以被工具、用户或外部信号验证。
- [ ] 输入材料位置明确。
- [ ] 修改范围可以限制。
- [ ] 存在状态文件或运行日志。
- [ ] 有停止规则。
- [ ] 有人工确认节点。
- [ ] 失败后可以回滚、暂停或交接。

建议暂缓进入 Loop 的信号：

- [ ] 任务目标还在变化。
- [ ] 没有反馈信号。
- [ ] 结果完全依赖审美、价值判断或商业判断。
- [ ] 涉及生产、权限、支付、数据删除、公开发布、商业上架。
- [ ] 用户不能接受中途暂停和复盘。

## 最小验收卡

```md
## 最小验收卡

- 本轮目标：
- 验收方式：
- 通过标准：
- 失败标准：
- 最大轮次：
- 最大时间：
- 最大成本：
- 必须人工确认：
- 禁止动作：
- 交付物：
```

## 断路器清单

以下任一条件触发时，应停止 Loop 并交给用户判断：

- 连续 2 轮出现同类失败。
- 任务范围从单文件扩大到多模块，且没有用户确认。
- 需要修改测试来让结果通过。
- 需要修改生产配置、权限、支付、数据删除或公开发布相关内容。
- 需要访问计划外仓库、账号、外部服务或敏感数据。
- 验收命令缺失或无法运行。
- Checker 无法独立判断结果。
- 状态文件与真实变更不一致。
- token、时间或 API 成本超过预算。
- Agent 开始生成无法验证的大段内容。

断路器输出格式：

```md
## 断路器触发

- 触发规则：
- 证据：
- 当前影响：
- 建议动作：停止 / 回滚 / 缩小范围 / 等待人工确认
- 需要用户确认的问题：
```

## 成本控制清单

设计 Loop 时默认加入成本预算：

- [ ] 最大轮次，例如 3 轮。
- [ ] 最大时间，例如 30 分钟。
- [ ] 最大 token 或 API 成本。
- [ ] 每轮只保留必要上下文。
- [ ] 长日志先摘要，再交给 Agent。
- [ ] 先跑只读侦察，再决定是否进入执行。
- [ ] 先手动跑通一次，再考虑低频周期化。
- [ ] 对探索类任务设置候选数量上限。
- [ ] 对内容类任务设置字数、候选标题、素材数量上限。
- [ ] 对代码类任务设置目录、文件、命令上限。

成本复盘问题：

- 本轮花费是否换来了可复用资产？
- 哪些上下文可以下次复用？
- 哪些步骤可以改成清单或模板？
- 哪些任务不值得进入 Loop？

## 7 天落地计划

适合用户从零搭第一个 Loop。

### Day 1：选一个小任务

- 选择低风险、反馈清晰、范围小的任务。
- 写出目标、成功标准和禁止动作。
- 建立 TODO.md state file。

### Day 2：做只读侦察

- 只读取文件、日志、现状。
- 输出计划和验收方式。
- 不修改文件。

### Day 3：跑第一轮 Maker

- 只做一个最小修改。
- 记录变更和原因。
- 交给 Checker 验收。

### Day 4：补断路器

- 根据前三天的问题补停止规则。
- 写清人工确认节点。
- 标出高风险动作。

### Day 5：形成模板

- 把可复用 Prompt、TODO.md、验收卡沉淀到模板库。
- 删除只服务单次任务的上下文。

### Day 6：换一个相邻任务验证

- 用同一套结构处理一个相邻任务。
- 观察模板是否需要改。

### Day 7：复盘是否升级

- 判断是否继续手动运行。
- 判断是否需要低频自动化。
- 判断是否值得沉淀为 Skill 或项目规则。

## 复盘清单

每次 Loop 结束后回答：

- [ ] 本轮目标是否完成？
- [ ] 成功标准是否清楚？
- [ ] Checker 是否真的独立验收？
- [ ] 哪些步骤依赖用户判断？
- [ ] 哪些错误可以提前拦截？
- [ ] 成本是否可接受？
- [ ] 是否有计划外改动？
- [ ] 是否需要更新 AGENTS.md？
- [ ] 是否值得沉淀为 Skill？
- [ ] 是否能转成内容案例或教学素材？

## 资产沉淀位置

| 资产 | 适合沉淀到哪里 | 例子 |
| --- | --- | --- |
| 项目长期规则 | `AGENTS.md` | 禁止改测试迎合结果 |
| 单任务状态 | `TODO.md` | CI 修复轮次和验收记录 |
| 可复用 Prompt | Skill 或模板库 | Maker / Checker prompt |
| 失败经验 | 失败报告 | 成本超限、范围越界 |
| 内容素材 | 内容素材库 | Loop 实战案例 |
| 长期流程 | Skill | 内容生产 Loop、学习复盘 Loop |

## Human3.0 对齐检查

- [ ] 人保留最终判断权。
- [ ] Agent 负责准备证据、执行低风险步骤和记录状态。
- [ ] 每次运行都能沉淀数字生产资料。
- [ ] 模板可以迁移到新任务。
- [ ] 复盘结果能进入个人系统。
- [ ] 自动化没有替代人的价值判断。
