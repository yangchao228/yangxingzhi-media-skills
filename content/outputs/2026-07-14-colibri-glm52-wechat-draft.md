# Colibrì v1.7.0发布：25GB内存跑7440亿参数，本地AI门槛真降了吗？

> 8月13日，DeepSeek 开放了1.6万亿参数模型 V4 Pro-0813 的权重；8月20日，Colibrì 更新到 v1.7.0。模型还在变大，个人设备也在寻找新的运行方式。Colibrì 已经能让25GB电脑启动7440亿参数的GLM-5.2，但约372GB本地权重和0.05—0.1 token/s的冷运行速度，说明容量门槛下降只是第一步。

8月20日，Colibrì 发布 v1.7.0。

截至当天核验时，它在 GitHub 上已有 **25,554 Star、2,773 Fork**。一个多月里，这个项目已经从围绕 GLM-5.2 的验证，扩展成支持六个模型家族、提供 Linux、macOS 和 Windows 预编译包的推理引擎。

一周前，DeepSeek 刚刚开放 V4 Pro-0813 的模型权重。它拥有1.6万亿总参数、490亿激活参数，官方权重约865GB。开放模型的规模仍在快速上升，个人设备的内存和显存却没有同步增长。

两个事件放在一起，问题变得更具体：权重可以开放下载之后，普通人距离真正把模型运行在自己手里，还有多远？

它做了一件反差很大的事：在一台消费级电脑上，用约 25 GB 内存运行 7440 亿参数的 GLM-5.2。

7440 亿参数是什么概念？

这类模型通常属于服务器和多卡工作站。只按每个参数 1 字节粗略计算，也需要数百 GB 容量。Colibrì 的核心推理引擎由 C 编写，不依赖 BLAS，也不强制要求 GPU，却能把这类模型放到普通电脑上执行。

看到这里，很容易得出一个兴奋的结论：超大模型终于可以装进个人电脑，本地 AI 平权来了。

结论下得太早，会错过这个项目真正有价值的部分。

## 25GB 为什么真能跑

关键先藏在 GLM-5.2 的架构里。

GLM-5.2 是 MoE 模型。它虽然拥有 7440 亿总参数，但处理一个 token 时，并不会同时调用全部参数。按照 Colibrì 的项目口径，每个 token 实际激活约 400 亿参数。

这给工程实现留下了空间。

Colibrì 把模型拆成两部分：经常需要的 dense 部分常驻内存，大量路由专家留在硬盘。当前 token 需要哪些专家，程序就把哪些权重从 NVMe 读进来，用完再继续处理下一批。

项目 README 给出的数字很具体：

- 常驻的 dense 部分约 170 亿参数，int4 量化后约 9.9 GB；
- 19,456 个路由专家保存在本地磁盘，完整容器约占 372 GB；
- GLM-5.2 路径最低要求 16 GB RAM，24 GB 会更宽松。

它把显存、内存和存储看成一套连续的资源层级。最快但最小的显存放热点数据，内存承担常驻部分，容量最大的 NVMe 保存暂时用不到的专家。

所以，“约 25 GB 内存运行 7440 亿参数”并非造假。更完整的表述是：一台拥有约 25 GB RAM 和足够本地高速存储的电脑，可以执行保留全量专家的 int4 量化版 GLM-5.2。

参数没有消失，只是大部分时间待在硬盘里。

## 容量省下了，时间要补上

把权重留在硬盘，解决了“装不下”的问题，也把瓶颈推给了磁盘带宽。

Colibrì 的 README 写得很坦率：冷解码时，每生成一个 token，大约需要从磁盘读取 11 GB 数据。项目开发机的磁盘吞吐约为 1 GB/s，对应的冷运行速度只有 0.05—0.1 token/s。

0.1 token/s 意味着生成 10 个 token 大约要等 100 秒。

项目当前汇总的实测覆盖了更宽的硬件范围：25 GB 开发机冷运行约 0.05—0.1 token/s；128 GB 的纯 CPU 桌面设备预热后约 1.8 token/s；单张 RTX 5070 Ti 设备约 1.07 token/s；当 6 张 RTX 5090 让权重完整驻留时，解码可以达到约 5.8—6.8 token/s。

这些测试的硬件、参数和缓存状态并不统一，不能当成严格横评。它们至少能说明两件事：低内存启动已经实现；速度取决于有多少专家能留在 RAM 或 VRAM，以及其余权重能以多快的速度从磁盘进入计算链路。

还有几个条件经常从传播标题里消失：

- x86 电脑需要支持 AVX2；Apple Silicon 使用单独的 NEON / Metal 路径；
- GLM-5.2 模型容器需要约 372 GB 本地 NVMe 空间；
- 当前推荐的是第三方制作的 gs64 int4 容器，并搭配 int8 MTP head；
- 项目明确提醒不要继续使用早期 per-row int4 镜像：受控测试显示其质量约低 9 个百分点，还曾导致思考模式循环和生成无法结束；
- v1.7.0 已提供三大桌面平台的预编译包，但项目仍把自己定位为开放的推理系统研究平台，不承诺统一速度。

因此，Colibrì 已经超出一次性演示的阶段，但把它描述成“普通电脑流畅运行满血大模型”，仍会把容量、速度、量化质量和硬件条件混成一个结论。

## 1.6万亿参数开放，部署还没跟上

DeepSeek V4 Pro-0813 把这个矛盾推得更远。

它和 DeepSeek V4 Flash 都属于 `deepseek_v4` 架构，规模却差了一大截。V4 Pro 有61层、7168 hidden size和384个路由专家；V4 Flash是43层、4096 hidden size和256个路由专家。

Colibrì 当前明确支持的是2840亿总参数、130亿激活参数的 **DeepSeek V4 Flash**。现有引擎按照 Flash 的张量形状、专家数量和内存规划实现，不能直接把 V4 Pro 的模型目录传进去运行。

这条边界很重要。

开放权重解决的是“能不能获得模型”。本地部署还需要推理引擎理解模型结构，需要量化和存储格式，需要内存规划，也需要用真实 checkpoint 验证输出正确性。

V4 Pro 已经可以下载，不代表一台普通电脑今天就能把它变成可用服务。按照 Colibrì 当前的支持矩阵，想本地尝试 DeepSeek V4，现实选项仍是约167GB权重的 V4 Flash；V4 Pro 还需要新的适配工作。

模型发布速度正在超过个人部署能力。这正是 Colibrì 这类项目值得关注的原因：模型公司负责开放能力，推理系统决定这些能力能不能真正进入个人设备。

## 真突破是重画资源边界

如果 Colibrì 还不够快，它为什么会受到这么多关注？

因为它改变了问题的问法。

过去谈本地超大模型，默认前提是权重要进入显存或内存。硬件容量不够，讨论便结束了。

Colibrì 给出的答案是：模型可以分层存在。常用部分留在高速资源里，海量专家放到便宜的大容量存储中，再用预取、缓存和调度换速度。

这个思路并不保证今天就好用，却打开了几条值得继续走的路：

第一，个人开发者可以直接研究原本只属于服务器集群的模型结构。以前连启动都做不到的问题，现在可以在本地观察、修改和验证。

第二，存储也开始成为推理系统的一部分。未来更好的专家预测、更高缓存命中率、更快 SSD 和更合理的 GPU offload，都可能继续抬高本地设备能执行的模型上限。

第三，模型运行位置重新变成一个可以选择的问题。数据是否离开设备、模型版本由谁控制、服务是否依赖外部平台，都可以按照任务重新配置。

过去一个多月的项目演进也验证了这条路线的可扩展性。当前同一套 `coli chat`、`coli serve` 和 `coli web` 前端已经连接六个模型家族，覆盖从 7B 的 OLMoE 到 2.8T 的 Kimi K3。GLM-5.2 仍是参考模型，存储分层已经不再只服务一个模型。

这才是 Colibrì 的长期价值：它把“个人电脑绝对跑不了”推进到“个人电脑能跑，但还要解决体验”。

## 普通人先按任务选择

看到本地大模型热点，最容易走进一个误区：把“能部署最大的模型”当成目标。

模型应该服务任务。不同任务，对速度、隐私、成本和控制权的要求完全不同。

如果你每天写作、搜索、编程，希望开箱即用并获得稳定速度，云端 API 或成熟应用仍然更合适。你购买的是吞吐、服务和省心。

如果你的资料敏感，需要离线运行，也希望获得正常交互速度，参数更小、生态成熟的本地模型通常更实用。此时优先看任务效果、上下文、显存占用和工具兼容性。

如果你在研究 MoE、本地推理、存储分层，或者想亲手验证个人设备能把超大模型推进到哪里，Colibrì 很有价值。你接受速度和配置成本，换取完整的实验空间。

三个选择没有高低之分。先确认任务，再决定模型放在哪里，往往比追逐最大参数更有效。

## 本地 AI 的门槛只降了一层

Colibrì 降低的是容量门槛。

速度门槛仍在，372 GB 的存储门槛仍在，量化后的质量验证仍在，安装和稳定性门槛也仍在。

技术进步很少在一天内完成“平权”。它通常先让少数人能够实验，再让工程方案逐渐成熟，最后才变成普通人可以无感使用的产品。

对个人而言，更有价值的能力也不在拥有最大的模型。你需要知道数据放在哪里、计算在哪里发生、每一种便利付出了什么成本，并为自己的任务保留切换方案。

个人 AI 系统的控制权，来自这些具体选择。

在 25 GB 电脑上，Colibrì 依然很慢；作为一个推理引擎，它已经拥有正式版本、多模型支持、预编译包和持续的性能与正确性测试。Star 数量说明关注度，版本演进和可复现数据才决定它能走多远。

它把一条原本关闭的路打开了：超大模型不再天然只能待在云端。

至于这条路多久能走进日常使用，要看接下来的磁盘带宽、缓存策略、专家预测和硬件协同能走多远。

如果速度慢十倍，但数据和模型都留在自己的电脑里，你愿意为这种控制权付出多少等待时间？欢迎在留言区说说。

模型能在本地启动，是控制权的起点；人能按任务自由切换，才真正拥有自己的 AI 系统。
