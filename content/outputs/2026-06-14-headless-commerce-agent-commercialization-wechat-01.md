# 2分钟500单：Agent 商业化的第一站，可能是一家电商店

## 导读

一个独立开发者用 v0 和 Cursor 搭了一个潮牌 drop 页面，上线 2 分钟处理 500 多单。这个案例的价值，落在电商链路正在变成 Agent-ready 的商业基础设施。想做 Agent 商业化，第一步不一定是做一个万能 Agent。更稳的起点，是先跑通一条可交易、可验证、可复盘的收款闭环。

## 01 一个两分钟处理 500 单的网站，暴露了新的商业入口

2026 年 6 月 11 日，Vercel CEO Guillermo Rauch 发了一条推文。

推文里只有一个网站链接：superbape.com。

这是一个潮牌限时发售页面。更让人停下来的，是它背后的数据：上线 2 分钟，处理 500 多个订单。

放在几年前，这种页面听起来像一个小团队项目。

你需要前端工程师做页面，需要后端工程师接商品和订单，需要运维扛流量，还要有人处理部署、缓存、监控、支付和异常。

这一次，故事变了。

这个站点由一个独立开发者搭出来，用到的工具是 v0、Cursor、Next.js、Shopify Storefront API 和 Vercel。

Rauch 在推文里写了一句话：

> Anyone can now dream → build → ship → sell.

任何人现在都可以从想法走到构建、上线和销售。

这句话听起来很燃。但如果只把它理解成“AI 写代码更快了”，就看浅了。

这个案例把一件事摆到了台面上：

**一个人已经可以用 AI 工具跑通一条生产级交易链路。**

对正在研究 Agent 商业化的人来说，这比“又一个 AI 建站案例”更重要。

因为商业化最终要落到交易。有人看到商品，有人加入购物车，有人完成结账，有订单、有库存、有履约、有复盘。

Agent 不能永远停在聊天框里。它要进入商业世界，迟早要碰到商品、价格、库存、支付、订单和售后。

电商就是一条现成的商业闭环。

## 02 Headless 电商把“页面”和“交易能力”拆开了

先把 headless 电商说清楚。

传统电商模板像精装房。

你用 Shopify 默认模板、淘宝店铺装修、某个 SaaS 模板开店，页面、商品、购物车、结账通常绑在同一套系统里。它的好处是上手快，坏处是你要按平台给你的方式来。

Headless 电商像一套开放的商业后台。

后端负责商品、库存、购物车、结账、订单。前端页面自己写，React、Next.js、小程序、App、任何能调用 API 的界面都可以接上来。

结果是，商品和交易能力不再被某个页面模板锁死。

这个差异很关键。

人买东西需要页面：图片、文案、按钮、交互、信任感。

Agent 买东西不需要逛页面。它更需要结构化接口：商品列表、价格、库存、规格、购物车、结账链接、订单状态。

人看到的是页面。

Agent 读取的是数据。

这就是 superbape 这类 headless 架构值得重视的地方：同一套商业后台，可以服务人，也可以逐步服务 Agent。

今天它是一个潮牌发售页面。明天它也可以是个人 IP 周边店、数字产品商店、课程售卖页、咨询预约页、会员权益页。

只要商品、库存、价格和结账都能通过接口被调用，它就具备了 Agent-ready 的基础。

## 03 Agent 商业化不该从万能 Agent 开始

很多人一谈 Agent 商业化，脑子里会出现一个很大的目标：

做一个能自动找客户、自动沟通、自动报价、自动成交、自动交付的智能体。

这个目标太大了。

它会同时碰到获客、信任、支付、售后、风控、法律、权限和人工接管。任何一个环节没设计好，项目都会卡住。

更务实的起点，是先选一条足够窄的交易链路。

比如：

- 一个数字产品；
- 一套资料包；
- 一件限量周边；
- 一个咨询预约；
- 一个课程名额；
- 一个小众品牌 drop。

这些场景有共同特点：SKU 不复杂，交易动作清晰，履约边界明确，用户不需要在海量商品里反复比较。

它们适合一个人用 AI 工具先跑起来。

你不需要一开始就让 Agent 接管全部业务。你先把最小链路跑通：

商品被创建出来。

页面被生成出来。

用户能看到商品。

用户能加入购物车。

用户能跳转结账。

订单能被后台记录。

这条链路跑通以后，你才有资格继续问：Agent 能在哪一步介入？

它可以帮你生成商品页。

它可以帮你整理商品描述。

它可以帮你检查库存和价格。

它可以帮你做用户问答。

它可以帮你把重复订单和售后问题汇总成报告。

商业化不能先许愿一个全自动系统。商业化先要求你有一条能验收的交易链路。

## 04 这次变化，来自 AI 工具和商业基础设施的会合

三年前，一个独立开发者想上线一个能扛住抢购流量的电商站，成本并不低。

至少要会前端、会后端、懂部署、懂支付，还要处理缓存、CDN 和异常情况。

现在的链路被拆开了：

- v0 生成前端 UI；
- Cursor 补全业务逻辑；
- Shopify 管商品、库存、购物车和结账；
- Vercel 管部署和访问性能；
- GitHub 管代码版本。

每个工具只解决一段问题。

AI 的作用，是把这些成熟基础设施串起来，变成普通人也能操作的执行层。

过去你卡在“我不会写页面”“我不会接 API”“我不会部署”。

现在，这些卡点都可以被 AI 工具部分接管。

人的工作也随之变化。

你要决定卖什么。

你要判断用户为什么买。

你要设定页面风格。

你要确认价格、库存、发货和售后。

你要检查 AI 接出来的链路是否真的能跑。

这就是 Human3.0 里很现实的一层变化：执行越来越便宜，判断越来越值钱。

一个人能不能跑通商业闭环，关键不只在代码能力，也在系统设计能力。

## 05 Headless 对 Agent 的意义，已经进入协议层

如果只是说“未来 Agent 会买东西”，这句话很容易变成科幻判断。

但电商平台已经开始往这个方向补协议。

Shopify 官方文档里已经单列 Agentic commerce，讲的是 Agent 如何发现商品、构建购物车、创建 checkout、追踪订单。它还提到 UCP 和 MCP server 这类面向 Agent 工作流的基础设施。

这说明，Agent 购物还有比浏览器模拟点击更稳定的路径。

更稳定的路径，是结构化协议。

传统模板页面对 Agent 来说很脆弱。按钮位置变了，页面结构改了，弹窗多了，模拟点击就可能失败。

Headless 电商的优势在于，Agent 可以直接读取商品数据，创建购物车，拿到结账链接，再把高风险动作交给人确认。

这里有一个边界必须说清楚：支付和真实下单不应该轻易全自动。

Agent 可以帮你筛选商品、整理选项、构建购物车、比较价格、提醒库存变化。

但到了付款、发货、退款、改地址这些动作，早期最好保留人工确认点。

稳妥的 Agent 商业化，不会让 AI 偷偷替人花钱。好的系统会让 AI 负责整理和执行，让人负责确认和承担后果。

## 06 这对普通人有什么用

这件事和普通人有关系。

因为它把商业化门槛拆成了更小的步骤。

过去你想卖一个东西，可能会被一堆问题拦住：

我不会建站。

我不会写商品页。

我不会接支付。

我不知道怎么部署。

我没有技术团队。

现在可以换一种顺序。

先不用做复杂品牌，不用做全套商城，不用做自动客服，也不用做 Agent 全自动店长。

先跑一个最小实验：

1. 选一个真实商品，哪怕只是一个资料包。
2. 用 Shopify 或类似系统创建商品。
3. 用 v0 生成一个商品展示页面。
4. 用 Cursor 接入商品和购物车 API。
5. 部署到 Vercel。
6. 找 3 个朋友测试从浏览到结账的完整路径。
7. 把所有错误、修改和用户反馈记录下来。

你最后得到的是一条可复用链路。

你得到的是一条可以复用的交易 SOP：

- 下次换商品，不用从零开始；
- 下次换页面风格，不用重建后台；
- 下次加 Agent，不用让它模拟点击；
- 下次做资料包、课程、周边、咨询，都能沿用这条链路。

这就是数字生产资料。

它避开一次性的 AI 炫技，沉淀为一条以后能反复改造的商业管线。

## 07 三条行动路线

如果你看完这篇想动手，可以按自己的基础选一条路线。

### 如果你懂一点前端

直接做 headless demo。

路线是：

Shopify 创建测试商品 -> 跑通 Storefront API -> v0 生成首页和商品页 -> Cursor 接 API -> Vercel 部署。

你的目标要压到“商品展示 -> 加购物车 -> 跳转结账”。

熟练的话 1-2 天，新手 3-5 天。

### 如果你不懂代码

先用模板开一个真实商品页。

不要一上来就挑战 headless。

你先完成这几件事：写商品标题、定价、上传图片、配置支付、让一个朋友完整走一遍购买流程。

这个过程会逼你理解商业闭环。

等你知道商品、价格、支付、售后这些基础动作以后，再迁移到 headless 会轻松很多。

### 如果你正在做 Agent

优先研究接口，不要只研究网页自动点击。

你可以先做一个小 demo：

让 Agent 读取商品列表，筛选符合条件的商品，创建购物车，生成 checkoutUrl，然后暂停，等待人确认。

这就是一个很小的 Agent-ready commerce demo。

重点放在验证：Agent 能不能稳定读取商品、理解约束、构建购物车、在高风险动作前停下来。

## 08 下一篇，我会把这条链路拆成保姆级步骤

Rauch 那句话很适合作为这个案例的注脚：

> Anyone can now dream → build → ship → sell.

我更关心后半段：sell。

AI 写代码已经不稀奇了。更值得追踪的是：AI 能不能帮你把一个想法推进到可交易、可验收、可复盘的商业闭环。

对 Agent 商业化来说，电商是一个足够好的第一站。

它有商品，有库存，有购物车，有结账，有订单，有明确的结果。

你不用先做一个庞大的 Agent 公司。你可以先做一个小店，一个页面，一个商品，一次真实测试。

下一篇我会按步骤拆开：

- 怎么准备 Shopify 测试商品；
- 怎么用 v0 生成首页、商品页和购物车；
- 怎么让 Cursor 接入 Storefront API；
- 怎么用 Vercel 部署；
- 怎么验收这条链路真的跑通；
- 怎么把它改造成 Agent-ready 的交易资产。

如果你正在找 Agent 商业化的入口，先别急着做全自动。

先让一个商品被看见，被加入购物车，被带到结账页。

这一步跑通了，后面的 Agent 才有地方落脚。
