# STORM Research

## 目标

把一个模糊主题推进成可判断、可采证、可交接的研究结构。

本 skill 服务研究前置阶段，适合接在 `wenchang-orchestrator` 的定题之后、`wenchang-research` 的事实采证之前。它输出问题地图和可信度评审，不写文章。

## 使用边界

只做：

- 多视角扫描。
- 矛盾地图。
- 研究简报。
- 可信度评审。
- 后续采证计划。
- 给下一阶段的 `content_state` / `handoff`。
- 在用户明确要求时，把研究结构整理成可直接浏览的单文件 HTML 研究页。

不做：

- 不写公众号正文、知乎正文或小红书文案。
- 不把角色模拟回答当事实。
- 不声称提示词版等同完整 Stanford STORM 系统。
- 不用无来源社媒截图作为关键证据。
- 不替用户做最终发布、投资、医学、法律或财务判断。
- 不把 HTML 研究页做成营销 landing page 或替代正式文章。

如果用户要求写文章，先输出研究结构，再把结果交给写作 skill。

## 输入

接受以下任意一种输入：

- 一个主题或问题。
- 一段外部素材、链接摘要或文章摘录。
- 现有 `content_state`。
- 产品调研、学习计划、选题方向、商业判断问题。

如果目标读者、目标平台或使用目的不明确，但不影响研究拆解，先按“Human3.0 / AI 实践读者 / 公众号前置研究”作为默认值，不要中断。

如果研究目的会显著改变输出，例如投资决策、医疗建议、法律判断、生产事故复盘，必须降级结论并要求一手来源或用户确认边界。

## 标准流程

### 1. 多视角扫描

默认使用 5 个视角：

1. 实践者：每天处理这个问题的人。
2. 学者：长期研究这个领域的人。
3. 怀疑者：认为主流叙事有问题的人。
4. 经济观察者：关注利益、成本、激励和商业模式的人。
5. 历史观察者：把当前问题放进更长周期里看的人。

如果主题更适合其他视角，可以替换或新增第 6 视角，例如监管者、普通用户、失败案例、供应链、伦理研究者、工程维护者。

每个视角都要输出：

- 核心关切。
- 可能支持的判断。
- 可能反对的说法。
- 独有信息。
- 需要查证的问题。

### 2. 矛盾地图

必须找出：

- 直接冲突。
- 共识底座。
- 证据强弱。
- 关键盲点。
- 最值得继续查的 3-7 个问题。

冲突比金句重要。没有冲突时，也要说明是主题过窄、来源不足，还是视角选择不够。

### 3. 研究简报

输出一份面向目标读者的简报：

- 一段话摘要。
- 5 个关键发现，按可靠性排序。
- 每个发现的支持视角、挑战视角和证据状态。
- 一个隐藏连接。
- 一个行动建议。
- 一个前沿问题。

区分 `事实`、`推断`、`观点`。没有来源支撑的判断必须降级表述。

### 4. 可信度评审

必须输出：

- 每个关键发现的可信度评分。
- 最弱结论。
- 偏见检查。
- 缺失视角。
- 发布前必须人工核验的事实。
- 不适合进入下一阶段的判断。

### 5. 可选 HTML 研究页

当用户明确要求“HTML”“可浏览页面”“demo 页面”“研究看板”“给客户看”“方便用户查看”时，除标准 Markdown 研究结构外，可以生成一个单文件 HTML 页面。

HTML 页面必须服务研究查看，而不是写成文章或宣传页。

页面要求：

- 单文件 `.html`，可直接在浏览器打开。
- 不依赖外部 CDN、远程字体、远程脚本或外部图片。
- 使用内联 CSS；除非用户明确要求，不写 JavaScript。
- 中文为主，必要术语保留英文。
- 第一屏直接呈现研究主题、核心结论、使用的 skill 名称和可信度提示。
- 有目录导航或锚点，方便快速跳转。
- 至少包含这些区块：
  - Hero：主题、结论摘要、使用的 skill 名称。
  - Demo 说明：本次如何用 `storm-research` 处理主题。
  - 多视角扫描：用卡片或表格呈现视角。
  - 矛盾地图：突出直接冲突、共识底座、证据强弱、关键盲点。
  - 研究简报：摘要、关键发现、隐藏连接、行动建议、前沿问题。
  - 可信度评审：评分、最弱结论、偏见检查、缺失视角、必须人工核验项。
  - 后续采证计划：按优先级列出要查的问题和建议来源。
  - `content_state` / `handoff`：用可读代码块或结构化面板展示。
  - 下一步建议：是否进入 `wenchang-research`，以及原因。
- 视觉风格清晰、专业、有层次，适合展示给读者、团队或客户。
- 不使用大面积浮夸渐变、装饰性光斑或营销感过强的 hero。
- 不把页面做成只有标题和几段正文的 Markdown 转 HTML。

推荐文件命名：

```text
content/outputs/YYYY-MM-DD-<topic-slug>-storm-demo.html
content/outputs/YYYY-MM-DD-<topic-slug>-storm-demo-source.md
```

如用户只要 HTML，可以只生成 HTML；如果后续还要维护、复核或深采证，建议同时生成 `*-source.md` 作为研究源文件。

HTML 输出参考见：

- `references/html-output-template.md`

## 采证计划

本 skill 可以列出待查来源，但不要伪造查证结果。

优先建议这些来源：

- 论文、官方文档、原始报告、财报、发布公告、访谈、数据集、真实案例。
- 对产品、价格、政策、接口、公司信息等高波动事实，标记为“必须实时核验”。
- 对社媒材料，只能作为传播线索，不作为关键证据。

如果已经联网或用户提供来源，可以把已知来源放进 `accepted_inputs`，但仍要标注哪些结论需要 `wenchang-research` 继续采证。

## 模板资源

可复制 Prompt 和资料包模板见：

## HTML 输出验收

生成 HTML 页面后，至少做以下检查：

1. HTML 文件存在。
2. HTML 包含主题、`storm-research`、多视角扫描、矛盾地图、研究简报、可信度评审、后续采证计划、`content_state`。
3. 静态解析 HTML，确认关键 section id 存在，页面不是空白。
4. 运行 `git diff --check -- <html-file> <source-md-if-any>`。
5. 如果本仓有禁用句式或内容风格约束，扫描新增正文。
6. 如果环境允许，使用浏览器打开或截图检查首屏、导航和主要区块；如果不能浏览器验证，要说明只完成了静态检查。

## 与文昌链路的关系

推荐链路：

```text
wenchang-orchestrator -> 定题 -> storm-research -> wenchang-research -> 立骨 -> 起稿
```

当 `confidence_review.verification_needed` 为空且主题偏个人经验，可直接交给写作 skill；否则优先交给 `wenchang-research`。

遇到以下情况必须暂停：

- 出现 3 个以上同等强度主切口，需要用户选主线。
- 关键结论依赖未核验事实。
- 主题涉及医学、法律、金融、政策或高风险业务决策。
- 用户要求最终发布、投资、治疗、法律判断或公开上架。
